# Independent evidence for zffmpeg

Use the pinned FFmpeg build to establish observable behavior before changing
the implementation. The feature's contract decides what must match. Follow
[document authority](../../../port.md#document-authority) and
[TODO.md's gates](../../../TODO.md#gates); this skill does not widen support
or mark a task verified.

## Choose the procedure

| Work | Read |
| --- | --- |
| New vectors, fixtures, a comparison, or a recorded difference | [Reference comparisons](references/comparisons.md) |
| Truncation, limits, allocation failure, fuzzing, or harness cleanup | [Failure testing](references/failure-testing.md) |
| A stateful stream's drain, seek, reset, or timestamps | Also use [media-pipeline](../media-pipeline/SKILL.md) |
| A disagreement involving C promotions, rounding, or ignored errors | Also use [ffmpeg-c-semantics](../ffmpeg-c-semantics/SKILL.md) |

Read only the procedures the change needs. Load `zig-0-17` before writing
Zig and `zig-io` for file adapters, buffers and seeking.

## Workflow

1. Name the observable result and its comparison rule: samples, packets,
   parameters, metadata, timestamps, errors, or generated files. Read the
   active task and fixture contract. Keep required inputs and optional
   samples separate.
2. Establish expected results with the pinned reference and independent
   hand-checked cases. Record the source/build identity and commands. A
   fixture generated by FFmpeg still needs an explicit expected result.
3. Make the check fail for the defect being prevented. For a comparator,
   inject failed commands and wrong output/status into its predicate; for
   a regression, check the old behavior or make a targeted temporary
   mutation in an isolated copy. Never mutate the user's working changes.
4. Exercise the applicable failure paths with the existing helpers. A fuzz
   entry must demonstrate that its seeds reach its intended parser or
   decoder; executing the callback alone is insufficient.
5. Run the affected comparisons and repository checks required by the task.
   Report actual commands, required passed/failed/missing cases, optional
   passed/failed/skipped cases, and fuzz budget separately. Use TODO.md's
   existing progress card for completion evidence.

## Before accepting the result

- Both successful commands exited successfully and produced the expected
  kind of output before their payloads were compared.
- A recorded refusal checks its exact permitted status and diagnostic.
  Crashes, missing dependencies and unavailable reference components do not
  count as matching refusals.
- A normalization removes only differences allowed by the contract;
  negative/missing timestamps, stream identity and side data remain visible.
- Every `KNOWN_*` exception asserts the difference it claims and has its
  notes.md row. Do not add an exception or widen a tolerance to hide a bug.
- FFmpeg reads actual Zig-generated media; a self round trip is supporting
  evidence, not the independent oracle.
- The harness owns and releases its own allocations and views correctly.
  A harness failure is investigated before it is attributed to the codec.
- The working tree did not change while a comparison, test or local CI run
  was in progress. No `git stash`, checkout or edit under a running build:
  the run would then describe a tree that never existed. Build another
  commit in a separate `git worktree`, and rerun anything a change raced.
- A seed run, mutation smoke, and sustained fuzz campaign are reported by
  their real names and budgets. A passing unit suite proves none of the
  unrun campaigns.
