# Revisable decisions

Project choices that could reasonably change later. The choices are project
policy, informed by the reference behavior and evidence linked below. They keep
each supported path small, strict and testable. Every entry names where the
choice lives, so a change can update those places together and re-run the
affected checks.

Authoritative details stay where they are: the WAV and AU contracts in
[port.md](port.md#first-wav-contract), their fixtures and precedence in the
[WAV](zig/testing/fixtures/README.md) and
[AU](zig/testing/fixtures/au/README.md) fixture READMEs, tasks in [TODO.md](TODO.md).
When you make a new revisable decision, add it here in the same change.

## Port design policy

The design review of 2026-11-03 supplied reasons for rules that must remain
visible as the port grows. These decisions live in the architecture and task
contracts; this section preserves their rationale without duplicating the
checklist or its status.

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Reference behavior | Within the supported surface the port matches the pinned FFmpeg, its bugs, quirks and departures from specifications and other implementations included (a decoder decodes as libavcodec does, not as the codec's reference library does), because the differential comparison against FFmpeg is the project's correctness rule and a fix would make every later comparison ambiguous. Each such behavior kept on purpose gets a row here, in its feature's section, naming the FFmpeg code, what the specification or other implementation does instead, and the checks that pin it; a test that would pass only against the other behavior is revised to FFmpeg's, with the reason recorded. | A deliberate departure needs its own decision here, a named option where it changes media, and a recorded difference in compare.py. |
| Supported surface | Explicit accepted subsets and exclusions. Every additional parser and recovery rule adds maintenance and untrusted-input paths; accepting everything FFmpeg accepts is not a goal. Failed experiments may be removed. | port.md "Supported scope and policy", the affected TODO.md G0 contract, fixture generator/README and reference differences. Excluded features also require revising "Not planned". |
| Checks and isolation | Check sizes before use in every mode; require named fixtures and a bounded fuzz entry before G5. Component selection should omit unused parsers. A Zig implementation is not a security boundary; applications retain responsibility for process isolation and privileges. | port.md's scope and resource rules, TODO.md coverage rules, T55 and T60. Record the changed bounds and evidence; a unit pass is not a sustained fuzz campaign. |
| Ownership and diagnostics | Types distinguish ownership where possible; APIs document remaining lifetimes and test failure cleanup. Allocators, I/O and diagnostic sinks are explicit dependencies. Copying an owner is not cloning it. | port.md "Core API and resource rules" and "Streaming state, ownership and time", TODO.md T14/T17a and the affected APIs and tests. |
| Algorithm duplication | Keep one implementation, specialized only for real variation. A second needs a purpose, comparison oracle and retention or retirement condition. Optimized kernels retain scalar; T24 has one native resampler. Shared contexts must not force unrelated codecs into one state model. | port.md's design goal, the consuming task and its tests; T58 for optimized variants. Follow each infrastructure task's Start-with note. |
| Time policy | Derive time from supported container/codec rules and integer counts; keep unavailable values null and preserve negative timestamps. Explicit rescaling, wrap handling and smoothing do not imply heuristic repair of broken streams. | port.md's time rules, TODO.md T15/T52 and affected timing vectors; update comparison normalization without hiding missing or negative values. |
| CLI policy | Library operation matrices govern commands. Reject unsupported combinations before creating output; media-changing defaults are named, documented options. Late parsing, writing and flushing errors remain failures after partial output. | port.md "CLI policy", TODO.md T13/T17a/T53 and process cases, including overwrite and cleanup behavior. T51's compatibility mode stays separate from the stable probe report. |
| Performance claims | Language choice establishes no speed advantage. Compare against both the C-only oracle and an asm-enabled FFmpeg benchmark build; keep their identities and results separate. SIMD also needs scalar equivalence and a measured gain. | port.md "Verification strategy", TODO.md T57/T58 and benchmark reports. Declare float tolerances before measuring; do not widen them to pass. |

Historical sources explain these choices, rather than establish the port's
current safety or completion. The
[2014 Google fuzzing report](https://security.googleblog.com/2014/01/ffmpeg-and-thousand-fixes.html)
records recurring bounds, pointer, cleanup and initialization failures and
recommends privilege separation. FFmpeg's pinned
[undefined-behavior note](https://github.com/FFmpeg/FFmpeg/blob/5d5a38a7e46be296eab75982c0986054f731e19e/doc/undefined.txt)
explains why signed overflow remains unsafe even on invalid input, and the
[send/receive contract](https://github.com/FFmpeg/FFmpeg/blob/5d5a38a7e46be296eab75982c0986054f731e19e/libavcodec/avcodec.h)
requires explicit progress, draining and reset behavior. The response here is
checked arithmetic and tested contracts; Zig alone supplies neither ownership
proof nor codec correctness.

## Test fixtures

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Generator language | Python 3, standard library only, so fixtures are built independently of the Zig code and can be generated where no Zig is installed. CI needs `python3`. | Rewrite `generate.py` in Zig if Python becomes a burden; keep the bytes identical so hashes still match. |
| Committed outputs | `.wav` files, `manifest.zon` and the README table are generated and committed; `--check` fails on drift. `.gitattributes` keeps `.wav` binary. | Generating at build time would remove committed binaries but needs a Zig build step and loses the independent generator. |
| Large vectors | The 2 MiB skip vector is described and hashed but built at test time, to keep the repository small. | Commit it if build-time construction proves error-prone. |
| Failure names | The `Failure` enum uses the contract's error names (`InvalidRiff`, ...) rather than snake_case, so tests can compare with `@errorName`. | `zig/testing/fixtures.zig` and `generate.py` together. |
| Allocation-failure sweeps and fuzz smoke (review P1) | `zig/testing/hostile.zig`'s `checkAll` fails each allocation in turn with every resize and remap failing too: growth then always takes an allocation that can fail (`toOwnedSlice` after a failed remap, review M8), and the allocation count stays deterministic, which it is not when resizes reach `std.testing.allocator` (whether one succeeds in place depends on earlier runs). The fuzz entries' seeds are laid out as `Smith` reads them outside the fuzzer (a `u32` length, the bytes, then `u64` values for the options); raw fixture bytes as a seed read as a length prefix and usually give an empty input. One `zig build test --fuzz` run failed locally ("corrupted coverage file ... pcs_len was zero"); another, with `-Doptimize=ReleaseSafe`, ran the VLC, Vorbis, Opus and oggdecode entries for 0.2 to 0.8 million inputs each without a finding. So `mutationSmoke` also mutates each seed a fixed number of rounds from a fixed PRNG seed in every test mode. The Ogg, MP3, generic-layer, ID3 and MPEG audio parser entries (T27a, T29a) use it. The codecs' sweeps (VLC, Vorbis, Opus, oggdecode: T18c, T27d, T28) use `checkAllocationFailures`, with resizes working and then failing, or only failing where a full sweep is slow in Debug. Every older fuzz entry's corpus uses `fuzzSeed` too since the review of 2026-11-05. | `hostile.zig`; a working `--fuzz` replaces the mutation smoke as the recorded budget (T60). |

## WAV contract

All of these are stricter than FFmpeg's `wavdec.c`, which ignores `riff_size`,
stops at end of input and accepts more variants. Each change needs `generate.py`
rerun, the [fixture README](zig/testing/fixtures/README.md) decisions table and
port.md's contract table updated, and (after T06) the parser.

| Decision | Current choice and reason | Fixtures |
| --- | --- | --- |
| Supported subset | Little-endian RIFF/WAVE, RF64/BW64 and Sony Wave64 (T21b) with the WAV PCM encodings (T21a: tag 1 at 8, 16, 24, 32 or 64 bits, tag 3 float at 32 or 64, A-law, mu-law, and WAVE_FORMAT_EXTENSIBLE with those subformats), 1 to 64 channels since T23b (`Limits.max_channels`, libswresample's `SWR_CH_MAX`; more is `LimitExceeded`, though FFmpeg reads them); everything else is `UnsupportedFormat`. | `fmt_*`, `extensible_*`, `rifx_*`, `rf64`, `bw64`, `w64_*` |
| Wave64 | One parser and writer for both chunk layouts (`wav.Variant`), since everything after the chunk framing is WAV's; detection names it `w64` from its `riff` magic. Sizes are read and written as the Sony specification has them (header counted, padding not); FFmpeg's muxer counts the padding, so its padded 24-byte plain `fmt ` is accepted too. Unknown sizes follow `unknown_length`, though FFmpeg's demuxer rejects them. FFmpeg also rejects an empty `data` chunk (24 bytes), which the writer emits for zero frames. | `w64_*`; `Variant` in `wav.zig`, `canonical_w64` in `generate.py`, the `w64` cells in `compare.py`. Counting the padding as FFmpeg does would make odd-sized data decode its pad bytes. |
| Wave64 duration | zffprobe reports the frame count from `data`'s size. FFmpeg's Wave64 demuxer sets no duration from it, and libavformat estimates one from the bit rate over the bytes from the data's start to the end of the file, so pad bytes and later chunks count as frames. compare.py computes FFmpeg's figure for each Wave64 fixture (`w64_differences`) rather than listing them. | `w64_differences` in `compare.py`; a reported duration would follow FFmpeg only by porting the estimate. |
| `fmt ` sizes | 16, or 18 with `cbSize == 0`; extensible exactly 40 with `cbSize == 22`. Fewer than 16 declared bytes is `InvalidFormat`; other sizes are `UnsupportedFormat`. | `fmt18_cbsize0`, `fmt_size_14`, `fmt20_cbsize2`, `extensible_fmt18`, `extensible_cbsize_short` |
| Whole-byte depths | Tag 1 takes 8, 16, 24, 32 or 64 bits, float 32 or 64, G.711 8; FFmpeg rounds other depths up. Odd depths in the wild are rare, and rounding would decode samples the header misdescribes. | `fmt_bits12`, `fmt_float_bits16`, `fmt_alaw_bits16` |
| Extensible details | Valid bits must be 0 or all bits; FFmpeg trusts them. A partial-valid-bits mode needs a recorded use first. Since T23b any channel mask is read as FFmpeg reads it: native when it names exactly the channels, else unspecified. The subformat GUID is read as `parse_waveformatex` reads it: a format tag in the KSDATAFORMAT, ambisonic B-format or "broken" shifted KSDATAFORMAT family, the last two refused until the review of `e7461c9` (Low-18); the writer writes KSDATAFORMAT only, as `ff_put_wav_header`. | `extensible_valid_bits_*`, `extensible_mask_*`; the GUID families in `wav.zig`'s unit test |
| `byte_rate` | Ignored, even when inconsistent, because decoding never uses it and real files get it wrong. | `byte_rate_mismatch` |
| Sample-rate limit | 192,000 Hz default; above it is `LimitExceeded`. A configurable policy limit, not a format rule. | `mono_192k_rate_limit`, `fmt_rate_over_limit` |
| Chunk-count limit | 4,096 chunks including `fmt ` and `data`; the 4,097th is `LimitExceeded`. | `chunks_at_limit`, `chunks_over_limit` |
| Retained-bytes limit | 1 MiB of non-audio bytes the parser keeps; skipped chunk bodies do not count, so large `LIST`/`id3 ` chunks stay readable. | `large_skip_2mib` (synthesized) |
| Streaming work buffer | No whole-file allocation: the parser works in a small stack buffer and the file adapter's buffer is 64 KiB by default ("Working storage" below). | A buffer size, not a format rule: no fixture. |
| Unknown sizes | `riff_size` 0 or 0xFFFFFFFF and `data` size 0xFFFFFFFF are `UnsupportedStreamingSize` by default. Since T21b the parser option `Limits.unknown_length` reads them to the end of the input instead: the extent may then end between chunks; unknown data must end on a whole frame, has no frame count, and nothing after it is read (FFmpeg's reading, so a known `riff_size` goes unchecked). Opt-in because it gives up the extent checks; the converter refuses unknown-length input because the writers need the length, and the CLIs do not enable it. `data` size 0 stays an empty stream, where FFmpeg reads to the end. | `riff_size_*`, `data_size_unknown`, `unknown_length_*`, `unknown_riff_*`, `empty_data`; changing it touches `Limits`, `Info.frame_count`, the manifest's `unknown_length` field and `compare.py` |
| Extent bounds | A chunk running past the RIFF extent, or fewer than 8 bytes left for a header, is `InvalidRiff`; input shorter than the extent is `Truncated`; bytes after it are ignored. FFmpeg tolerates all of these. | `*_exceeds_riff_extent`, `partial_chunk_header_in_extent`, `riff_size_exceeds_input`, `trailing_bytes_after_riff` |
| Final pad byte | A pad byte outside the extent is not read (accepted); one inside the extent but missing is `Truncated`. | `odd_final_chunk_pad_*` |
| Duplicates and order | Exactly one `fmt ` before exactly one `data`; a second `fmt ` (which FFmpeg ignores) or `data` is `InvalidWave`. | `duplicate_*`, `data_before_fmt`, `missing_data`, `no_chunks` |
| Partial frames | A `data` size that is not a multiple of `block_align` is `InvalidFormat` (FFmpeg drops the partial frame). | `data_not_block_aligned` |
| Error precedence | First violation in stream order; within `fmt `, tag, bits, channels, rate, `block_align`, then size. | `rifx_truncated`, `fmt_unsupported_before_invalid`, `data_size_unknown` |
| Partial output | Errors found after audio was produced are still reported; output is not atomic. | `duplicate_data`, `chunk_exceeds_riff_extent` |

## Container limits

Policy limits shared by the parsers, each a configurable `Limits` field;
FFmpeg has none of them. Each is `LimitExceeded`.

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Channels | 1 to 64 in WAV, Wave64, AU, AIFF, CAF and raw (libswresample's `SWR_CH_MAX`, so every stream can be converted); FFmpeg reads more (`*_channels65` fixtures in each contract). | `max_channels` in each parser; the fixture READMEs. |
| Sample rate | 192,000 Hz by default in every parser and the raw writer (`max_sample_rate`). An AIFF rate above it is refused before conversion, where FFmpeg truncates an 80-bit rate that overflows its `int`. | `max_sample_rate`; `aiff.sampleRate`. |
| Chunk count | 4,096 chunks in WAV, AIFF and CAF (`max_chunks`), against chunk-flooding input. | `max_chunks`. |

## Writer

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| RF64 | Read: RF64 and BW64 with a 28-byte `ds64` first and no size table, stricter than FFmpeg (which ignores the 32-bit size and the table). Written: `WriteOptions.rf64 = .auto` by default, deciding up front from the known length, where FFmpeg's default `never` writes broken sizes past 4 GiB; `.always` exists to compare small RF64 files with FFmpeg. | `wav.zig`, the `rf64*` fixtures, `write_driver.zig` (`rf64` argument). |
| Header format | Since T21a, the `fmt ` FFmpeg's `riffenc.c` chooses: extensible above 48 kHz or above 16 bits unless float, else plain (16 bytes for tag 1, 18 with `cbSize` 0 otherwise), plus a `fact` chunk for every encoding but tag 1, which FFmpeg writes on seekable output and we always can. This replaced T08's tag 1 at every rate: TODO.md T21a asked for FFmpeg's choice, and plain high-rate files remain accepted input. Compare decoded samples and metadata with FFmpeg, not file bytes (FFmpeg adds LIST/INFO). | `canonical_wav` in `generate.py`, `Writer` in `wav.zig`, the writer-output fixtures. |
| Known length | The frame count is required up front and exact sizes are written with no seeking, except for a decoded Ogg or MP3 input into a WAV, AU or AIFF output that can seek back (a regular file): its header then says no frames and is rewritten at the end (`beginDeferred`, `rewriteHeader`; "Deferred header"). | T08; other inputs without a count (raw PCM from a pipe, FLAC without a total, WAV of unknown length) could take the deferred header too. |
| Wave64 output | `WriteOptions.variant = .w64`: the same `fmt ` as WAV, a `fact` chunk with a 64-bit count for every encoding but tag 1, sizes without padding, and the file below 2^63 bytes (FFmpeg reads sizes as signed). `rf64` does not apply. | `wav.zig` `Writer`, `canonical_w64`, the `w64` writer-output fixtures. |
| Empty non-PCM `fact` | For an empty stream of a non-PCM encoding the writer's `fact` count is 0; FFmpeg's WAV muxer writes 1 (its sample count is 0 − `INT64_MAX`, truncated to 32 bits), found by the rematrix comparison. The port writes the count the file holds. | `wav.zig` `Writer`; compare.py's remix section compares raw samples, so it does not see it. |

## PCM, audio and time types

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Public API shape | `zig/root.zig` exports flat namespaces `av.pcm`, `av.audio` and `av.time`. | Reorganize before external users depend on the names. |
| PCM kernel API | `decodeS16` / `encodeS16` over caller slices, byte order as a `comptime` parameter (both orders exist). Scalar only; no SIMD yet. | Add SIMD kernels only with comparisons against the scalar ones (port.md). |
| Kernel failures | A failing call writes nothing; input and output must not overlap, asserted only in Debug and ReleaseSafe. Frame ranges outside a `samples` buffer are checked errors, in every build mode: `decode`'s offset past the buffer is `OutputTooSmall` and `encode`'s frames past it `InputTooSmall`, since a debug assert would let ReleaseFast read or write past the buffer. | `zig/codec/pcm.zig` docs and tests. |
| Rounding | Callers always pass a `Rounding`; there is no implicit default. FFmpeg's `av_rescale_q` uses `nearest`. | Add a defaulting helper in `zig/core/time.zig` if call sites repeat `.nearest`. |
| Rescale edge cases | Exact `i128` arithmetic. Overflow is `error.Overflow` (FFmpeg returns INT64_MIN) and `minInt(i64)` rescales exactly (FFmpeg treats it as -INT64_MAX). | `rescale` and its tests; T03/T10 differential checks should expect these two differences. |
| FFmpeg's rescaling (T15) | `rational.rescaleRnd` restates `av_rescale_rnd` with its `INT64_MIN` results and wrap-around, a second implementation of rescaling beside `time.rescale`. Purpose: code that models FFmpeg's own arithmetic (demuxer timestamps, seeking) must reproduce its overflow results; oracle: vectors/rational.txt from the pinned libavutil. `time.rescale` stays the API for new code. Retire one if every caller can use the other. | `core/rational.zig`, `core/time.zig`. |
| Time-base range | `TimeBase` has positive `u32` fields, unlike FFmpeg's signed `int` `AVRational`; negative or zero time bases are rejected. | Widen the fields if a format needs time bases beyond `u32`. |
| Missing timestamps | `?i64` (`null`), never a sentinel such as `AV_NOPTS_VALUE`. | Every API that carries timestamps. |
| Channel layouts | `audio.Format` carries a `channel_layout.Layout` (T23b): FFmpeg's native, custom and unspecified layouts of 1 to 64 channels ("Channel layouts" below). T01's mono and stereo only are gone. | `core/audio.zig`, `core/channel_layout.zig`. |
| Sample-rate policy | `audio.Format` accepts any nonzero `u32` rate; the 192 kHz cap is each parser's configurable policy ("Container limits"). | Keep limits in the parsers' configurable options. |
| Example promotion | The former `zig/examples/pcm_s16.zig` was moved into `zig/codec/pcm.zig`; examples now cover only I/O patterns. | Re-add examples only for patterns not shown by library code. |

## WAV parser, writer and file adapters

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Parser API | `wav.Parser`: `readHeader`, `readSamples` (s16 storage) and `readData` (any encoding, T21a), `finish`; `collectTags` before `readHeader` (T21c); `seekFrame`/`seekFile` with a seeker (T52a). `wav.probe` validates without decoding and `wav.decodeToRaw` streams raw s16le. Validity requires `finish`, which skips unread data and checks the rest of the extent. | `zig/format/wav.zig`. |
| One PCM data path (T65b) | `format/pcmdata.zig`'s `Data` reads the sample data of WAV, Wave64, AU, AIFF, CAF and raw PCM: whole frames still encoded (`readData`) or decoded to s16 (`readSamples`, decoding a frame wider than its scratch in the output's own memory), the skip of the rest with frame counting (`skipRest`), and `decodeToRaw`'s loop; `writeS16` is the writers' encoding loop. Headers, limits, error precedence, padding and what follows the data stay per format. The project owner chose to make the empty result mean the end of the data only: an output that cannot hold one frame while data remains is `OutputTooSmall` (it was an empty result, so a caller could not tell it from the end, which T13a worked around by sizing its buffers). For data of unknown length the end is found by peeking one byte; a reader without a buffer cannot peek, so there such an output is `OutputTooSmall` even after the last frame. A parser read before its header reads as the end of no data, and `readSamples` on a codec not stored as s16 is `UnsupportedFormat`, where both were assertions. | `pcmdata.zig` and its tests; the parsers' `readSamples` and `readData`. |
| Working storage | 4 KiB on the stack per read or write call; no allocator for the audio. Collected tags (T21c) allocate with the caller's allocator, within `Limits.max_retained_bytes`. The 64 KiB figure is the recommended file-adapter buffer (`file.default_buffer_len`). | Raise `scratch_len` only with a measured benefit. |
| Configurable limits | `wav.Limits` exposes `max_sample_rate` (192 kHz), `max_chunks` (4,096), `max_retained_bytes` (1 MiB, the tag chunks read when the caller collects tags, T21c) and `unknown_length` (T21b). | `wav.Limits`; the fixture contract's limit rows. |
| Writer limits | `wav.Writer.begin` rejects rates above `Limits.max_sample_rate` (`LimitExceeded`) and sizes beyond 32 bits (`SizeOverflow`) before writing anything; frame-count errors leave the writer usable. A format of no channels is `InvalidFormat` in the WAV, AU, AIFF and raw writers and `file.writeFile`, as `avcodec_open2` refuses an encoder without channels; before, they divided by zero (review Low-16). | `zig/format/wav.zig` and its tests. |
| File reading | `decodeFile`, and `probeFile` on a pipe or terminal, use `readerStreaming`; `probeFile` and zffmpeg read a regular file positionally from offset 0, so Ogg's duration scan and seeking can go back (T27a). Standard input redirected from a regular file is such a file (see "I/O and API"). | `zig/io/file.zig`, `zig/cli/ffmpeg.zig`. |
| Error detail | File adapters return the file's own error (for example `NotOpenForReading`, `Canceled`) instead of `IoFailure`/`WriteFailed`. | `withReadCause` / `withWriteCause` in `zig/io/file.zig`. |
| Namespace | The adapters are `av.file`. | Rename before external users depend on it. |

## zffprobe and the FFmpeg reference

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Arguments | Exactly one path, or `-` for standard input; `-h`/`--help` prints help. No options yet. | `zig/cli/probe.zig` and the `probe_cases` in `build.zig`. |
| Vector file order | The generators that take fixture files (`seek_vectors.c`, `flac_vectors.c`, `ogg_vectors.c`, `mp3_vectors.c`, `vorbis_vectors.c`, `opus_vectors.c`) sort their arguments with `strcmp`, and the committed files list fixtures in that byte order. ## Undefined C behavior

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Follow the reference build | Where FFmpeg's C is undefined but the reference build (Clang, Linux x86-64) gives a definite result, the port computes that result, as FFmpeg's output on the reference platform is the comparison: signed integer overflow wraps (SILK's arithmetic, rematrixing's integer mixes, the mpegaudio parser's `header_count` after 2^31 matching headers, `ff_gen_search`'s interpolation between timestamps far apart, `ff_find_last_ts`'s doubling step near 2^63, read_frame_internal's priming and discard-padding sums, the AAC parser's frame count after 2^31 frames (at 2^32, where FFmpeg's average divides by zero, the port leaves the bit rate as it is), the MP2 encoder's analysis filter, `idct32` and fixed-point quantizer), an integer stored in a narrower signed type keeps its low bits, as Clang does with C's implementation-defined conversion (Ogg Vorbis' `os->end_trimming = skip` from an `int64_t`, read_frame_internal's `int discard_padding`, the MP2 encoder's `int bitrate = avctx->bit_rate`), shift counts are taken mod 32 (LPC's `512 >> pass`, the dither's `1 << (8 * bytes)`), a double out of range or NaN converts to `INT_MIN` or `INT64_MIN` (expressions, asetpts' `D2TS`, where `INT64_MIN` is no timestamp) and to `uint64_t` as Clang lowers it, and `lrint` as "Undefined C cases" under sample format conversion says. ARM and Windows builds of FFmpeg give other results (saturating conversions, a 32-bit `long`). FFmpeg has no special case for NaN or infinity in these conversions: the result is whatever instruction the compiler emits for the C, so it depends on the compiler, its version, the CPU and FFmpeg's own build options (x86asm and NEON kernels replace the C for some pairs). Zig's float-to-integer conversion (`@trunc` or `@intFromFloat` into an integer type) must therefore never stand in for C's: out of range or NaN it is illegal behavior, a panic in Debug and ReleaseSafe and an arbitrary value in ReleaseFast that can change with the LLVM version and the target. Such conversions go through `core/cconv.zig`, which models the reference build's instructions (`lrintf`/`lrint` as a 64-bit `cvtss2si`/`cvtsd2si`, `lrintfInt` for `int = lrintf(double)`, `cvttsd2si32` for a plain store into `int32_t` or `int16_t`, such as the MP2 encoder's float quantizer, `rint`) with NaN and the range checked first, so the port's result is the same on every compiler and CPU. A float-to-integer `@trunc` elsewhere needs a range proof beside it. | Each site names it in a comment; T62-T63 decide per platform whether to follow FFmpeg's build there, which then changes `cconv.zig` alone. |
| Undefined memory | Where FFmpeg reads memory it never wrote for the stream, the port picks a fixed value: the FLAC parser's stale ring byte reads 0 ("Parser reads"), an Opus channel FFmpeg leaves unwritten is silence ("A silenced channel takes stream 0's first channel"). Fixtures avoid these cases. | The feature's row. |
| Refused instead | Where FFmpeg crashes, divides by zero or reads out of bounds, the port refuses or fails the frame: "Refused where FFmpeg runs" (filters, CELT) and "Undefined cases in the hybrid path" (Opus). | The feature's row. |

## Sample format conversion

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Kernels (T23a) | `resample/audioconvert.zig` reproduces libswresample's direct conversion (`full_convert`, no resampling, rematrixing or dither) for every pair of the twelve formats, bit-exact on the 280 vectors of the pinned libswresample (the `edge` pattern: NaN, infinities, overflowing products and ties), floats included: integer shifts, round-to-nearest-even int-to-float conversion times an exact power of two, and float-to-int `lrint` (half to even) with clipping. | `audioconvert.zig`, `sampleconv_vectors.c`. |
| Undefined C cases | FFmpeg converts float and double to s16 and u8 with `av_clip_int16(lrintf(x * (1<<15)))` and `av_clip_uint8(lrintf(x * (1<<7)) + 0x80)`, with no case for NaN or infinity. `lrintf` returns a 64-bit `long`; its value is unspecified for NaN, infinity and products beyond the 64-bit range. The clip functions take an `int`, so the `long` is narrowed to its low 32 bits first. On the pinned build here (Clang 23.1.4, Linux x86-64, `--disable-x86asm`), `libswresample.a`'s `conv_AV_SAMPLE_FMT_FLT_to_AV_SAMPLE_FMT_S16` inlines `lrintf` as `cvtss2si %xmm, %r64`, which gives `INT64_MIN` for NaN, infinity and overflow, and then clips the low 32 bits. Measured over 20 values from f32 and f64 input, FFmpeg's output is exactly `clip(low32(lrint64(x * scale) [+ 0x80 for u8]))`. NaN and ±inf become 0 in s16 and 128 in u8. Finite products from 2^31 to 2^63 wrap before clipping: 65536.0 becomes -32768, 131072.0 becomes 0 and -65537.0 becomes 32767. The port computes the same through `core/cconv.zig` (`lrintf`/`lrint`, then `@truncate` to 32 bits, then the clip); `cconv.zig`'s tests check its rule against all 2^32 float inputs' worth of FFmpeg's C expression as hashed on 2026-11-05, and `sampleconv_vectors.c`'s `edge` pattern pins it. Before that fix the port clipped the 64-bit value (NaN gave -32768), which was the reference job's 176 local float failures. CI's Clang 18 build was recorded as giving -32768 for NaN and +inf; that would need a 32-bit `cvtss2si` and was never verified, so the reference is the C as written with a 64-bit `long`, as the pinned build computes it. s32 (`av_clipl_int32(llrint(...))`) and s64 have no narrowing, and the port matches them. Other builds of FFmpeg give other results: x86asm's SSE kernel (`cvtps2dq`, then `packssdw`) saturates every out-of-range sample to -32768 or 32767; ARM's `fcvtns` saturates before the narrowing, so +inf gives -1 in s16; Windows' 32-bit `long` overflows already at 2^31. | `core/cconv.zig`; `convertSample` in `audioconvert.zig` and its tests; `sampleconv_vectors.c`'s `edge` pattern; `compare.py`'s float fixtures. |
| Pipeline (T23a) | `Frame` holds any sample format; `pcm.Decoder` and `pcm.Encoder` take every codec in its storage, and `audioconvert.Converter` sits between them when the storages differ. `compare.py` checks every converted zffmpeg output by decoding it and FFmpeg's own conversion (as raw PCM of the codec) to the same samples. | `frame.zig`, `pcm.zig`, `convert.zig`, `check_converted`. |
| Scope decisions | The project owner chose FFmpeg's automatic conversion to the output's default codec when transcoding, plus `-c:a` to pick another, and every dither method, noise shaping included. | TODO.md T23a; port.md. |
| Dither (T23a) | `resample/dither.zig` reproduces libswresample's `dither_method`, `dither_scale` and `output_sample_bits` bit-exactly (137 vectors of the pinned libswresample, including a `dither_scale` of 1000 and 10^9, where the noise leaves the internal format and wraps through `swri_get_dither`'s `int16_t`/`int32_t` store, `cconv.cvttsd2si32`): the internal format, the noise generator and its buffer (twice the largest call, at least 65536 frames, restarting when a call would pass its end), `sum2`'s wrapping integer mix, and the noise-shaping filters in FFmpeg's float and double arithmetic, falling back to triangular high-pass without a filter within 5% of the rate. ## I/O and API

| Decision | Current choice and reason | To change it |
| --- | --- | --- |
| Field reads | `readSliceAll` into local arrays instead of `takeInt`, so parsing works with any reader buffer size, including zero. A failed read is terminal for the stream. | CLAUDE.md, port.md "Verified Zig 0.17 I/O choices", `io_patterns.zig`. |
| Field writes | Encode into a local array and `writeAll`, instead of relying on `Writer.writeInt` working below its documented buffer minimum. | Same places. |
| Error spelling | `Canceled`, Zig's `std.Io.Cancelable` spelling, not `Cancelled`. | port.md error list. |
| Sequential parsing | The first parser is synchronous and blocking through `*std.Io.Reader`; resumable nonblocking parsing is a separate future capability. | port.md "Recorded design decisions". |
| Bounded skips | Zig 0.17.0's `Reader.discardShort` adds the count to its buffer position unchecked (`seek + n`), and `discardAll`/`discardAll64` go through it, so a chunk size near 2^64 (2^32 on 32-bit targets) panicked in safe builds and rewound the position in ReleaseFast. Every skip of a length read from a file in the PCM containers (WAV, Wave64, AIFF, CAF, AU, raw and `mov_chan`) goes through `io/skip.zig`, which discards at most 2^30 bytes per call with the std's short-count and `EndOfStream` results (review M1). | `zig/io/skip.zig`; retire it when the std checks the addition, and report the std bug upstream. |
| Reader mode | A regular input file is read positionally (`file.reader`), anything else streaming (`readerStreaming`), decided by `stat().kind`. Sequential reads cost the same in both modes, but a streaming reader's skips read every byte and it cannot seek back: skipping 1 MiB after each 4 KiB read was 15× faster positionally, 16 MiB 260× (the `zig-io` analysis, R3 and S1). | `zig/cli/ffmpeg.zig`, `file.probeFile`; `file.decodeFile` still streams (the analysis' "Findings"). |
| Buffer size | 64 KiB for file and pipe readers and writers (`file.default_buffer_len`). Reads peak at 16–64 KiB, writes of small pieces need 64 KiB or more, pipes are bound by the kernel (the `zig-io` analysis, R1, W1, R4); FFmpeg uses 32 KiB, 64 KiB on pipes. | `zig/io/file.zig`; remeasure with the skill's `bench/run_all.sh` before changing it. |
| No threads in the pipeline yet | Conversion runs demux, decode, filter, encode and mux in turn on one thread. A reader and a worker joined by an `Io.Queue` halved throughput for 4 KiB packets and gained 3% for 64 KiB ones; FFmpeg's thread-per-component scheduler used 20× the syscalls and 4× the CPU of zffmpeg on the same WAV to AU conversion (the `zig-io` analysis, Q1 and E2E). | T53d and T59: add a thread or queue only with a measurement on the real codec showing a gain; record it in the analysis. |
| std.Io backend | `std.Io.Threaded` from `std.process.Init`. `std.Io.Evented` (io_uring) does not compile in Zig 0.17.0 (`Io/Uring.zig:759` sets a field `Io.VTable` lacks). | Revisit with a newer Zig: add an `evented` case to the skill's benchmark first. |
| I/O references, not dependencies | zio, ZLS and zig-cookbook are pinned clones in `.references/` for reading (README.md), with the toolchain's `lib/std` as the authority and a Zig clone read at the `0.17.0` tag for the library's tests and history (the release ships its tests empty; `master` had changed 223 `lib/std` files by 2026-11-06); none is a build dependency. zio (an async runtime implementing `std.Io`) and libxev (a callback event loop) were declined as dependencies: both target many concurrent network streams, which are not planned; zio links libc and libxev bypasses `std.Io`; the "Dependencies" row above forbids them without a port.md decision. | Reopen zio as a measured `std.Io` backend if T59 shows `Io.Threaded` limiting; libxev only if a scope decision adds network streaming. |
| Standard input from a regular file (open question) | When standard input is a regular file, zffprobe and zffmpeg read it like a named file: positionally from offset 0, its size giving raw PCM's frame count. FFmpeg's `pipe:` protocol never seeks: it streams from the descriptor's current offset, so with a descriptor already advanced the port rereads the consumed bytes and counts them: 4000 bytes of raw s16le with the first 1000 consumed by `dd` give 2000 frames in zffprobe and 1500 decoded by the pinned ffmpeg. Whether to adopt "`pipe:` never seeks" is open; it would change raw-PCM frame counts and Ogg durations on `-` input (review Low-11). | `file.probeFile`, `file.regularLength`, `zig/cli/ffmpeg.zig`'s input reader. |
